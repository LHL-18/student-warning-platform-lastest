| 已有 | 状态 | 说明 |
|---|---|---|
| 三 Agent 预警分析流 | 已实现 | 预警分析师 → 帮扶规划师 → 执行监督员，对应 `CONFIG.real.skillId` |

**缺口**：任务流目前是「隐式」的——写在 `app.js` 的分支里，没有统一的流程定义、状态与追踪。下面给出 6 条建议任务流与一套轻量流程引擎设计。

---

## 二、设计原则

1. **双端同源**：学生端与教师端共享同一份任务流定义，只是视图与权限不同。
2. **人在环中（Human-in-the-loop）**：AI 只产出建议与证据，升级/解除预警等关键动作必须由人确认。
3. **闭环**：每条流都要有「触发 → 分析 → 干预 → 核查 → 归档 → 回流特征」的收口。
4. **可观测**：每个节点记录 输入快照 / 输出 / 耗时 / 引擎（真实 or 降级）/ 操作人。
5. **可降级**：模型不可用时流程不中断，标记为「降级数据」继续走。

## 三、六条建议任务流

### 任务流 1 · 拍照错题闭环流（学生端 · 最高优先级）

```
触发：学生上传/拍摄错题照片
  │
  ├─① 图片预处理（压缩 1280px、可选旋转校正）
  ├─② 级联 OCR：本地 Tesseract → qwen-vl-plus（置信度不足时升级）
  ├─③ 知识点识别：知识库 RAG 匹配 Top3 知识点
  ├─④ 大模型解题：思路 / 完整解答 / 易错点 / 同类练习
  ├─⑤ 学生确认 → 存入错题本（未掌握）
  ├─⑥ 复习排程：3 天后 / 7 天后 / 15 天后推送复习提醒
  ├─⑦ 复习打卡：点「复习一次」→ reviewCount+1、状态转「复习中」
  └─⑧ 掌握判定：连续 2 次自我判定通过 → 标记「已掌握」
        │
        └─ 回流：错题知识点分布 → 写入学情画像「薄弱知识点」维度
               → 同一知识点错题 ≥3 次 自动触发「学业预警」候选
```

| 项 | 内容 |
|---|---|
| 参与角色 | 学生（主）、辅导员（可见汇总） |
| 关键数据 | 错题本记录 `{知识点, 原题, 解答, 复习次数, 状态}` |
| 异常分支 | OCR 失败 → 提示手动输入题目文字；模型失败 → 降级 Mock 并标注 |
| 评价指标 | 错题沉淀率、7 日复习率、知识点掌握转化率 |

**为什么值得做**：把「答疑」变成「可追踪的学习资产」，同时天然产出预警所需的薄弱知识点数据，形成学生端与预警端的闭环。

### 任务流 2 · 语音学业求助与分流流

```
触发：学生在「困难申报」页长按/点击「语音描述」
  │
  ├─① ASR 实时转写（麦克风）或上传录音 → 文本
  ├─② 意图识别（小模型/大模型分类）：
  │     学业困难 / 心理压力 / 经济困难 / 宿舍生活 / 紧急心理危机
  ├─③ 风险分级：
  │     普通 → 生成工单，指派辅导员，48h 内响应
  │     紧急（自伤/危机关键词）→ 立即弹窗提示心理危机热线 + 通知辅导员 + 标记「最高优先级」
  ├─④ 生成结构化申报单（学生可编辑确认）
  ├─⑤ 辅导员接单 → 干预建议（大模型辅助）→ 处理记录
  └─⑥ 回访与结案 → 满意度评价 → 归档
```

| 项 | 内容 |
|---|---|
| 参与角色 | 学生、辅导员、心理中心（可选） |
| 关键数据 | 申报单 `{类型, 紧急度, 转写原文, 处理记录, 状态}` |
| 异常分支 | 拒绝麦克风 → 退化为文字申报；ASR 失败 → 手动输入 |
| 评价指标 | 首次响应时长、结案率、紧急事件 100% 触达率 |

> 注意：心理相关数据属高敏感信息，建议单独加密存储、单独授权，不进预警评分模型，只做分流与提醒。

### 任务流 3 · 课堂多模态采集 → 画像更新流（教师端）

```
触发：教师上传课堂材料 / 作业照片 / 阶段性成绩单（可批量）
  │
  ├─① 分类：成绩单 / 作业 / 实验报告 / 点名表
  ├─② 级联 OCR 取文本 → 结构化抽取（姓名、学号、分数、缺勤）
  ├─③ 数据校验：学号匹配失败 / 分数越界 → 进入「待人工确认」列表
  ├─④ 写入学业数据（保留原始图片作为证据链）
  ├─⑤ 特征更新：成绩趋势、作业完成率、出勤率
  └─⑥ 触发评分规则 → 命中阈值则生成预警工单（进入任务流 4）
```

| 项 | 内容 |
|---|---|
| 参与角色 | 任课教师、辅导员、教务管理员 |
| 关键数据 | 原始文件 + 结构化记录 + 置信度 + 人工确认标记 |
| 异常分支 | 抽取置信度低 → 一律人工确认，不自动入库 |
| 评价指标 | 录入耗时下降率、抽取准确率、人工复核率 |

**亮点**：这是「多模态」最能被评委看到价值的地方——把教师每学期的重复录入工作变成一次拍照。

### 任务流 4 · 学业预警帮扶闭环流（三 Agent 升级版）

```
触发：规则引擎命中 / 教师手动升级 / 任务流 1·3 回流特征命中
  │
  ├─【Agent1 预警分析师】输入画像+多模态特征 → 风险等级、风险因素、证据
  ├─【人】辅导员确认预警（可调整等级）
  ├─【Agent2 帮扶规划师】生成个性化帮扶方案（学习计划 / 资源 / 辅导频次）
  ├─【人】辅导员审批方案（可编辑）
  ├─ 执行期：学生每日打卡（文字/拍照/语音）→ 完成度计算
  ├─【Agent3 执行监督员】按周核查：完成度、成绩变化 → 通过 / 不通过
  │     ├─ 通过 → 进入解除审批
  │     └─ 不通过 → 升级干预强度（增加辅导频次 / 二级预警 / 通知家长）
  └─ 结案归档 → 沉淀「有效干预方式」到案例库 → 反哺下一次方案生成
```

| 项 | 内容 |
|---|---|
| 参与角色 | 辅导员、院系领导、学生 |
| 关键数据 | 工单状态机 `待干预 → 帮扶中 → 核查中 → 已解除 / 已升级` |
| 异常分支 | 学生连续 3 天未打卡 → 自动提醒 + 通知辅导员 |
| 评价指标 | 预警解除率、平均干预周期、干预方案采纳率 |

**改进点**：现有实现已有状态机与操作日志，建议补上「审批节点留痕」与「案例库反哺」。

---

### 任务流 5 · 学习计划伴学流（学生端）

```
触发：帮扶方案下发 / 学生自建目标
  │
  ├─① 生成周计划（任务 + 资源 + 预计时长）
  ├─② 每日推送当日任务（可按学生作息选择推送时间）
  ├─③ 完成任务：勾选 / 拍照上传作业 / 语音口述总结
  ├─④ 完成度计算 → 连续打卡激励（徽章、进度条）
  ├─⑤ 周报：完成率、薄弱点、下周计划调整建议（大模型生成）
  └─⑥ 连续未完成 → 通知辅导员（回流任务流 4 的监督节点）
```

| 项 | 内容 |
|---|---|
| 参与角色 | 学生（主）、辅导员（可见） |
| 关键数据 | 计划 `{周, 日, 任务, 资源, 完成状态, 证据}` |
| 异常分支 | 任务难度反馈过高 → 触发计划重排 |
| 评价指标 | 日活打卡率、周计划完成率、连续打卡天数 |

---

### 任务流 6 · 知识库沉淀流（教师端）

```
触发：教师上传课件 / 试卷 / 讲义
  │
  ├─① 真实解析（txt/md/csv/json/xlsx；pdf/docx 提示转换）
  ├─② 文本分块（600 字 / 80 字重叠）
  ├─③ 知识点抽取：标题、课程、难度、标签
  ├─④ 向量化入库（建议接向量库，当前为内存 + localStorage）
  ├─⑤ 关联知识点图谱（前置 / 后继）
  └─⑥ 供任务流 1 的答疑 RAG 与任务流 4 的学习资源推荐使用
```

| 项 | 内容 |
|---|---|
| 参与角色 | 任课教师、管理员 |
| 关键数据 | 知识点 `{课程, 标题, 摘要, 内容, 标签, 难度, 来源文档}` |
| 异常分支 | 解析失败 → 明确提示格式，不做静默失败 |
| 评价指标 | 知识点覆盖率、答疑命中率、教师上传量 |

## 四、轻量任务流引擎设计建议

不引入重型工作流引擎（如 Flowable）也能实现，建议用「JSON DSL + 状态机 + 执行器」：

### 4.1 节点类型

| 类型 | 说明 | 示例 |
|---|---|---|
| `trigger` | 触发节点 | 定时、表单提交、文件上传、规则命中 |
| `tool` | 工具节点（确定性） | OCR、ASR、文档解析、规则评分 |
| `llm` | 大模型节点 | 解题、生成方案、意图分类 |
| `human` | 人工节点 | 辅导员审批、学生确认 |
| `condition` | 条件分支 | 风险等级判定、置信度阈值 |
| `notify` | 通知节点 | 站内信、邮件、短信 |
| `end` | 结束节点 | 归档 |

### 4.2 DSL 示例

```json
{
  "id": "flow-wrongbook",
  "name": "拍照错题闭环流",
  "version": 1,
  "steps": [
    { "id": "ocr", "type": "tool", "tool": "ocr", "input": "${trigger.image}" },
    { "id": "check", "type": "condition", "expr": "${ocr.confidence} < 55",
      "then": "vlm", "else": "rag" },
    { "id": "vlm", "type": "llm", "model": "qwen-vl-plus", "prompt": "solve.md" },
    { "id": "rag", "type": "tool", "tool": "knowledge.match", "input": "${ocr.text}" },
    { "id": "solve", "type": "llm", "model": "qwen-vl-plus" },
    { "id": "confirm", "type": "human", "assignee": "${student.id}" },
    { "id": "save", "type": "tool", "tool": "wrongBook.save" },
    { "id": "end", "type": "end" }
  ]
}
```

### 4.3 运行要求

- **幂等**：每个节点带 `runId + nodeId`，重试不重复写库（当前错题本已按 id 去重）。
- **超时与重试**：模型节点超时 30s，失败重试 1 次后降级。
- **快照**：每个节点落库输入/输出摘要，便于「预警溯源」演示。
- **人工节点**：支持挂起 + 待办列表 + 审批留痕。
- **可观测**：一次运行 = 一条时间线，前端可直接渲染成流程图。

## 五、落地优先级建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 任务流 1（错题闭环）、任务流 4 补齐审批留痕 | 学生端有获得感、教师端有闭环，答辩最易演示 |
| P1 | 任务流 2（语音求助分流）、任务流 6 接向量库 | 体现多模态 + 安全合规，差异化亮点 |
| P1 | 轻量任务流引擎（JSON DSL） | 让「任务流」从代码里独立出来，成为可配置能力 |
| P2 | 任务流 3（课堂采集）、任务流 5（伴学） | 价值大但依赖真实数据与教师配合 |
| P2 | 移动端 / 小程序 | 学生使用场景主要在手机 |

## 六、其他发展建议

**功能层**

1. **证据链**：每条预警都能下钻到原始多模态证据（照片、录音、OCR 文本），答辩时非常有说服力。
2. **可解释性**：预警结论展示「命中了哪条规则 / 哪个特征贡献了多少分」，避免黑盒。
3. **申诉通道**：学生可对预警提出申诉，进入教师复核节点（任务流 2 的延伸）。
4. **隐私分级**：心理数据单独加密 + 单独授权，不进预警评分，只做分流。

**技术层**

5. **OCR 准确率**：对数学公式建议接专用公式识别（如 Mathpix 类）或在提示词中要求 LaTeX 输出。
6. **向量检索**：把 `knowledgeBase` 的内存打分替换为向量库（如 SQLite + sqlite-vec、或本地 embedding），提升 RAG 命中率。
7. **缓存与限流**：模型调用加结果缓存（同一图片 hash）与并发限流，控制成本。
8. **离线优先**：本地 Tesseract 保证断网也能用，联网时再升级大模型——这条链路本身就是亮点。
9. **数据看板**：错题知识点热力图、干预效果对比、预警趋势，直接复用现有 ECharts。

**答辩层**

10. **一键演示**：保留现有「启动演示」按钮，扩展为串起「拍照录入 → 预警生成 → 帮扶方案 → 打卡核查 → 错题本复习」的完整故事线。
11. **对比实验**：同一张错题图片分别用本地 OCR 与大模型识别的结果对比，直观展示级联策略的价值。
12. **降级演示**：主动断网演示系统仍可运行（Mock 兜底 + 本地 OCR），回应评委对「AI 不稳定」的质疑。
